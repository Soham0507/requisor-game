# AppViewX 47-Day Shootout

## Overview

This is a conference booth game called "AppViewX 47-Day Shootout" - an interactive basketball-themed web application designed for trade show engagement. The game features a March Madness-inspired UI where players complete certificate automation challenges, earn scores, and compete on a leaderboard. Built with a modern React frontend and Express backend, the application captures leads through email collection and stores game scores in a PostgreSQL database.

## User Preferences

Preferred communication style: Simple, everyday language.

## System Architecture

### Frontend Architecture
- **Framework**: React 18 with TypeScript
- **Build Tool**: Vite for development and production builds
- **Styling**: Tailwind CSS v4 with CSS variables for theming
- **Component Library**: shadcn/ui (New York style) with Radix UI primitives
- **State Management**: TanStack React Query for server state
- **Animations**: Framer Motion for game animations and transitions
- **Fonts**: Inter (body), Söhne (display/headlines, with Inter fallback), IBM Plex Mono (scores/captions/code)

### Backend Architecture
- **Runtime**: Node.js with Express
- **Language**: TypeScript with ESM modules
- **API Design**: RESTful JSON API under `/api` prefix
- **Static Serving**: In production, serves built frontend from `dist/public`
- **Development**: Vite dev server with HMR proxied through Express

### Data Storage
- **Database**: PostgreSQL via `pg` driver
- **ORM**: Drizzle ORM with drizzle-zod for schema validation
- **Schema Location**: `shared/schema.ts` (shared between frontend and backend)
- **Tables**:
  - `users`: Basic user authentication (id, username, password)
  - `scores`: Game scores with player info and stats
  - `email_captures`: Lead generation email collection

### API Endpoints
- `GET /api/scores` - Retrieve top scores for leaderboard
- `POST /api/scores` - Submit a new game score
- `POST /api/capture-email` - Capture email for lead generation

### Routing
- **Library**: wouter for client-side routing
- **`/`** — Main game flow (home → game → results with form → leaderboard)
- **`/display`** — LED wall display mode: full-screen leaderboard only, no forms, no navigation. Designed for 1280x1600 portrait LED walls at conferences. Auto-refreshes every 5 seconds. Scales to fit any viewport while maintaining 1280x1600 aspect ratio.

### Build Process
- Development: `npm run dev` runs Express with Vite middleware for HMR
- Production: `npm run build` uses esbuild for server and Vite for client
- Database: `npm run db:push` pushes schema changes to PostgreSQL

## External Dependencies

### Database
- **PostgreSQL**: Primary data store, connection via `DATABASE_URL` environment variable
- **connect-pg-simple**: Session storage in PostgreSQL (available but may not be active)

### UI/Component Libraries
- **Radix UI**: Full suite of accessible UI primitives (dialog, dropdown, tabs, etc.)
- **shadcn/ui**: Pre-built component library using Radix + Tailwind
- **Lucide React**: Icon library
- **Embla Carousel**: Carousel/slider functionality
- **cmdk**: Command menu component

### Validation & Forms
- **Zod**: Schema validation for API requests
- **drizzle-zod**: Generates Zod schemas from Drizzle table definitions
- **react-hook-form**: Form handling with @hookform/resolvers

### Development Tools
- **Vite plugins**: Custom meta images plugin, Replit-specific plugins for dev environment
- **PostCSS/Autoprefixer**: CSS processing
- **tsx**: TypeScript execution for development

### PWA / Offline Support
- **Manifest**: `client/public/manifest.json` - standalone mode, portrait orientation, Apple meta tags, brand colors
- **Service Worker**: `client/public/sw.js` (v10) - pre-caches all static assets including videos, fonts, HTML shell; cache-first for JS/CSS bundles
- **Full Offline Play**: Game is fully playable offline — HTML shell cached, all assets pre-cached
- **Offline Score Storage**: Scores saved locally via Cache API (`offline-local-scores`) and queued for server sync (`offline-score-queue`)
- **Auto Sync**: When connection resumes, queued scores flush to server automatically via `online` event + SW message
- **Leaderboard Fallback**: API responses cached (network-first); falls back to locally stored scores when fully offline
- **Online/Offline Indicator**: Header shows "System Operational" (green) or "Offline Mode" (yellow) based on `navigator.onLine`
- **iPad Install**: Open in Safari, tap Share > Add to Home Screen

### Video Playback
- **playSegment function**: Controls video playback with start/end times and speed per video ref
  - successVideoRef: plays 2-5s at 1.5x speed
  - miss1VideoRef: plays 0-4s at 1x speed
  - miss2VideoRef: plays 0-4s at 1x speed  
  - perfectVideoRef: plays 0-5s at 1x speed

### Environment Requirements
- `DATABASE_URL`: PostgreSQL connection string (required)
- `NODE_ENV`: Set to "production" for production builds
